## UI

**Требования к UI:**
- адаптивные размеры - не задаем все явно, расчитваем на систему. элементы сами подстраиваются. Определяем порядок элементов, но не фиксированные размеры и позицию, только относительные.
- Компактное расположение элементов. Приложение вспомогательное, не должно мешать пользователю. Всё должно быть четко, лакончино и интуитивно понятно. Расчитываем на простое понимаение, а не подробное описание.

### На ПК:

Процессы:
- Трей: процесс приложения живет, сохраняясь в трее. При выходе из трея приложение завершает свою работу.

#### Окна:
- `панель управления`
  
  **Поведение в системе:**
  - окно отображается в панели задач
  - запускается из трея
  - запускается при открытии приложения
  
  **Компаненты панели:**
  - Различные настройки. Расположены в таком порядке:
    - `Конфигурация` — кнопки слева направо:
      - `Сбросить настройки` — сброс общих настроек к значениям по умолчанию с подтверждением. Функция не затрагивает сценарии, историю записей и аудиофайлы: не изменяет и не удаляет их.
      - `Настройки (JSON)` — редактор текущей конфигурации с проверкой JSON перед сохранением. Кнопки: `Скопировать`, `Применить`, `Отмена`.
      - `Скопировать логи` — копирует логи приложения в буфер обмена
    - `Запуск приложения` — Переключатель между (по умолчанию не выбрано):
      - открывать окно при запуске ОС
      - открывать свёрнутым в панели задач
      - запускать скрытым в трее (не в панели задач)
    - `Общие настройки:`
      - Настройки провайдеров.
      Если провайдеро на том или ином шаге больше двух, то находим у них общие настройки.
      В таком случае для каждого провадера в `Конретные настройки` будет выбор inherit от настройки из `Общие настройки`, либо задать конкртено.
    - [](#сценарии-в-панели-управления)
  - Настройки `desktop overlay записи`:
    - сброс позиции (по умолчанию по середине снизу)
  - Блок "История записей":
    - в хедере задается значение - число последних сохраненых записей
    - список записей сгруппированые по датам.
      Каждая запись отображает:
      - название сценария
      - время: час:минуты
      - шаги выбранного сценария:
        - каждый шаг остаётся на своём месте независимо от результата: выполнен, отключён, не выполнен или завершился ошибкой; шаги не группируются по статусу;
        - статус ошибки и её текст показываются непосредственно у шага с ошибкой; статус невыполненного шага — непосредственно у него;
        - озвучка — плеер у своего шага: воспроизведение/пауза, перемотка, время; без повторного синтеза;
        - шаги идут друг за другом без соединительных линий, уровней и отдельной группировки ошибок или невыполненных шагов

        **Сохранение:**
        - результат или ошибка — в очередь сразу после шага; аудио озвучки — сразу после синтеза, до воспроизведения;
        - запись по порядку, без задержки следующих шагов; завершение сценария, включая ошибку и отмену, ждёт обработки всей очереди;
        - ошибка шага не отменяет очередь; ошибка записи не прерывает сценарий и последующие попытки сохранения;
        - при сбое базы, аварийном закрытии или отключении питания незаписанные данные могут потеряться.

        **Оформление:**
        - шаги отображаются компактным списком строго в порядке сценария;
        - после шага `транскрибация текста`, прямо внутри него и перед следующим шагом, отображается результат как в режиме редактирования из [](#интерфейс-редактирования-записи), но только для просмотра:
          - сегменты сохраняют итоговое включённое или отключённое состояние, без возможности переключения;
          - воспроизведение доступно по полоскам;
          - ПКМ по полосе — меню «Скачать» / «Транскрибировать и скопировать» для её сегмента, отрывка или всей записи; исключённые участки не включаются;
          - курсором можно выделять и копировать любой текст, включая отключённые сегменты; рядом с текстом — только «Копировать» для включённых сегментов;
          - без полос, при сохранённом аудио, — кнопка «Действия» с тем же меню для всей записи, в том числе после ошибки распознавания.

    - **Действия с аудио:**
      - `Скачать` — системный выбор имени и места сохранения; подтверждение после записи файла, отмена без сохранения.
      - `Транскрибировать и скопировать` — распознать выбранное аудио с текущими настройками и скопировать результат в буфер; историю не изменять, остальные шаги сценария не запускать.

        
  - Всё остальное, что необходимо по всему описанию приложения.

  **Горячие клавиши** (глобальные, работают независимо от активного окна):
  Пауза и отмена перехватываются только во время сценария или показа ошибки, а также при закреплённом оверлее; в простое клавиши свободны.
  - `старт/стоп записи` - по умолчанию `Ctrl+Shift+D` [](#ввод-клавиши) [](#настройка-из-панели-управления)
  - `пауза/возобновление` - по умолчанию `Ctrl+Alt+D` [](#ввод-клавиши) [](#настройка-из-панели-управления)
  - `отмена сценария` - по умолчанию `Escape`; останавливает выполнение сценария и сразу скрывает окно оверлея [](#ввод-клавиши) [](#настройка-из-панели-управления)

- `desktop overlay записи` - `окно оверлея`
  Свойства:
  - окно появляется:
    - виден от начала сценария до его завершения: после успеха скрывается сразу, после ошибки — по окончании её показа.
      - **Закрепление (ПК):** нажатие на оверлей выделяет его рамкой, приостанавливает следование за мышью и сохраняет видимым с содержимым после завершения сценария. Нажатие вне снимает выделение; завершённый оверлей скрывается, работающий — остаётся до завершения. Отмена сценария скрывает его сразу.
    - `Функция перемещения между мониторами`: регулируется по [](#значение-из-настройки). На мониторе, где находится мышка. При перемещении мышки на другой монитор - окно перемещается туда.
    - поверх всех окон
    - без иконки в панели задач
  - любой текст оверлея можно выделять и копировать
  - окно можно перетаскивать мышью — за значок или свободное место шапки. Позиция сохраняется при перемещении и не меняется при автоматическом изменении размера: [](#сохрание-в-настройках) [](#значение-из-настройки)
  - имеет максимальную ширину по отношению (0-100%, по умолчанию 50%) к размеру экрану монитора на котором находиться [](#значение-из-настройки)
    При появлении текста окно расширяется от центра в обе стороны. При достижении предельной ширины текст переносится на новую строку, а окно остаётся в пределах монитора.
    в настройках это:
    - [](#инпут-слайдер)
    - [](#динамичный-блок-скелет):
      - отобржается на мониторе в `окно оверлея`. 
        Изменение размера скелета происходит относительно блока оверлея.
        Позиция блока оверлея остается на месте, а блок скелета меняется по ширине, для этого меняется окно оверлея
      - высота транслирует высоту оверлея, меняется ширина

  **Состав блока оверлея:**
  - Отображение индикации шагов сценария, например:
    - **Блок шага:** заголовок со статусом; ниже — собственное тело, если есть, и ошибка. Пустое тело не занимает места; содержимое и ошибки не дублируются в общем теле оверлея.
    - **Порядок отображения:**
      - последовательные шаги сменяют друг друга;
      - параллельные — одновременно, вертикально, в порядке сценария;
      - в параллельной группе завершённые шаги сохраняют статус и тело до завершения всех действий, затем показывается следующий шаг.
    - записи:
      - статус: активна/неактивна
      - Во время `запись` отображается индикатор громкости входного звука (микрофона)
    - ошибки во время выполнения сценария
    - ошибку доступа или устройства с доступными действиями из раздела [](#доступ-к-микрофону)

  - Отображение `трансрибация в реальном времени`:
    - вкл/выкл `трансрибация в реальном времени` - флаг из [](#настройка-из-панели-управления) (по умолчанию вкл). В зависимости от флага отображаются настройки реально времени.

    Во время `запись` приложение отправляет аудио на распознавание небольшими фрагментами:
    - фрагмент завершается после паузы в речи: длительность задаётся [](#настройка-из-панели-управления) `Пауза для отправки` (по умолчанию 700 мс);
    - если речь продолжается, фрагмент отправляется по [](#настройка-из-панели-управления) `Максимум фрагмента`, по возможности у ближайшей паузы (по умолчанию 9 секунд);
    - соседние фрагменты перекрываются на [](#настройка-из-панели-управления) `Перекрытие фрагментов` (по умолчанию 0,5 секунды), чтобы не терять слова на стыках;
    - отображай весь накопленный текст записи с границами сегментов и отрывков, как в редакторе, но без полос проигрывания и действий редактирования;
    - после `возобновление` сохраняй весь текст и отметки удалённых сегментов из редактора; добавляй новую транскрибацию к этому тексту;
    - устраняй дубли распознавания перекрывающегося участка аудио; сохраняй реальные повторения слов в разных участках записи.

  #### Интерфейс редактирования записи:
  - `отрывок аудио`: При каждой `пауза` записи получаем отрывок аудио и отправляем на `трансрибация`. Транскрибаторы возвращают сегменты - привязка текста к времени в аудио. В оверлее появляется режим редактировани:
    - текст-транскрибация этого отрывка: визульно отображаются границы сегментов этого текста. При нажатии на сегмент или при долгом зажатии и проведении по сегментам, сегменты отмечаются как `удалённые` или наоборот `не удаленные`.
    - проигрывание аудио: под каждой строкой текста отображаются три уровня полос, сверху вниз:
      - первый — до конца сегмента;
      - второй — до конца отрывка;
      - третий — до конца всей записи.
      Проигрывание начинается с начала сегмента, соответствующего позиции нажатия на полосе.
      Во время проигрывания соответствующие полосы и текущие сегменты подсвечиваются.
      
    Удаленные участки текста и аудио визуально синхронизируются между собой.

  - И так происходит при каждой `пауза`. В оверлее отображаются все `отрывок аудио` горизонтально с момента начала записи до момента `пауза` и доступны для такого редактирования. Отображение компактное по тексту. Сегменты текста отображаются как обычный текст, только выделена грница между ними. Аудио отрезок отображается по ширине текст.
  Во время `остановка записи` все отрывки не удаленные текста объединяются в один - это и есть выходной текст из транскрибации.

### На Android

- Разрешения: кнопки оверлея и микрофона видны только без разрешения. Обновляй после запроса и возврата из настроек.
- Интерфейс максимально приблежены как [](#на-пк), но UX для пользователей смартфонов.
- Показывай Android Bubble при открытой клавиатуре, скрывай при закрытой. Поле ввода ищи только при вставке текста. Используй общий с ПК HTML/CSS/JS в WebView.
- Крестик скрывает Bubble до закрытия клавиатуры. При повторном открытии показывай снова, даже в том же поле. Разрешение специальных возможностей оставляй включённым.
- По нажатию кнопки запускай запись и показывай управление: индикатор голоса, закрыть, пауза, стоп.
- Под кнопками показывай текст транскрибации; на паузе — в режиме редактирования.
- На паузе открывается редактор. «Продолжить» сохраняет изменения и возобновляет запись. После завершения записи текст вставляется в активное поле.
- Фоновая запись выполняется через службу с уведомлением.
- Уровни истории буфера Windows на Android недоступны.
- Проверять на реальном телефоне.

## Сценарии

### Сценарии в панели управления


Интерфейс:
- **Список сценариев:**
  - **Хедер:** `раскрытие` + `переключатель` + `название` + `copy_button` + `reset_button` (при наличии) + `delete_button`.
  - **Тело:** шаги и настройки.
  - **Добавление:** `add_button` (`+`) внизу списка.
  - **Название:**
    - непустое, уникальное;
    - двойной клик по названию: вместо него — [](#инпут), текст выделен; `Enter` / потеря фокуса — сохранить, `Escape` — отменить;
    - нажатия на название не сворачивают сценарий; остальная часть хедера — сворачивает;
    - `add_button`
  - **Новый сценарий:** раскрыт, выключен, без триггера.
  - **Копия:** раскрыта; настройки, триггер и включённость сохранены.
  - **Удаление:** с подтверждением; после удаления фокус — на следующем сценарии, иначе на предыдущем.
  - **Статус триггера:** в хедере, виден и при свёрнутом теле.
- **Шаги:**
  Шаги описаны в [](#сценарии-приложения).
  Настройки шагов находятся внутри раскрываемых шагов и сохраняются отдельно в каждом сценарии. Показывай только настройки, доступные на текущей платформе и в текущем состоянии шага. Если доступных настроек нет, не отображай блок «Настройки».
  Уточнения:
  - Для шага `запись` в раскрываемых настройках доступен выбор микрофона; по умолчанию — системный.
  - Для `в буфер обмена` и `вставить в поле` — отдельный флаг «Показывать текст в оверлее» (по умолчанию выключен): отображает передаваемый текст в теле соответствующего шага.
  - **Озвучка — системный движок:**
    - настройки каждого шага: голос/язык, скорость, высота, громкость;
    - получение возможностей — по общему правилу для провайдеров ниже, без пробного синтеза; громкость при необходимости регулируй при воспроизведении.
  - `Конкретные настройки` для провайдеров:
      При выборе провайдера отображаем его настройки.
      
      Для каждого провайдера изучаем его API на предмет того, что мы можем отобразить в настройках:
      - то, что может возвращать сам API для отображения в настройках, но при этом не расходует лимиты/квоты и прочие ограничения пользователя. Например: список моделей, параметры, языки и прочее. В связи с особенностью каждого провайдера.
      - то, что API не возвращает описываем вручную по документации

      **API-проверка конфигурации провайдера**
      Для каждого провайдера изучить, есть ли у него способ проверить параметры настроек без расходования лимитов/квот и прочих ограничений пользователя.
      Если есть, то создать **фукнцию-проверку**:
        - сделай автопроверку. Срабаотывает при:
          - при первой инициализации окна
          - при изменении только тех параметров, используемых в API-проверке. Локально проверяемые настройки не вызывают повторный запрос.
        - добавить для этого провайдера кнопку «Тест», которая будет делать это.
      **Функция-проверка** отражается на статусе шага.

      Важные настройки, без которых провайдеры не сработают, визуально выделяем.  
  
  Интерфейс. Редактирование состава и порядка шагов сценария.
    **UI редактирования:**
    - выбор стартового шага;
    - добавление — кнопка `+` раскрывает выбор совместимых шагов: на вертикали — последовательный шаг, на горизонтали — параллельный;
      - `+` перед меткой данных — только при горизонтальном разветвлении; вертикальная группа `сквозное действие` его не добавляет;
    - настройки отображаются при раскрытии шага; сохраняются отдельно для каждого шага.
    - **Параллельная группа для `сквозное действие`:**
      - карточки вертикально в общей рамке;
      - от общей линии данных — ответвления к карточкам и селектору добавления; правила выполнения — по [](#логика-сценариев);
      - управление — отдельно у каждого шага;
      - вход и выход общие, без повторов типа данных между карточками; последовательное продолжение — за рамкой, после обозначения типа данных.
    - **Параллельные ветки для `преобразование`:**
      - колонки фиксированной ширины; начало развилки — на одной горизонтали, далее ветки растут вниз независимо;
      - ветка с ответвлениями занимает свою область; соседние колонки сдвигаются вправо без пересечений линий; настройки и текст — в пределах колонки;
      - ширина блока — по содержимому, не больше доступной в окне; при переполнении — горизонтальная прокрутка.
    - добавление и изменение шагов сохраняют положение прокрутки.
    - шаги с одинаковыми типами входа и выхода можно отключить; отключённый шаг остаётся в цепочке, помечается и передаёт данные дальше без изменения, его можно включить обратно.
    
    **Визуальное оформление шагов:**
    - сообщение об ошибке конфигурации
    - линии последовательных и параллельных шагов прямые; тип данных расположены на связи;
    - `источник` обозначен точкой, `преобразование` — узлом `Δ` на линии;
    - для `сквозное действие` линия проходит через шаг и ответвляется к карточке.
    Например:
    - `[Шаг 1: Триггер записи] → [Аудио] → [Шаг 2: Транскрибация] → [Текст] → [Шаг 3: Вставить в поле] → [Текст] → [Шаг 4: В буфер обмена]`.

#### Индикация выполнения сценария

- **Только линии данных, в каждой ветке отдельно:**
  - выполнение — вращающийся индикатор;
  - переход между шагами — короткий световой импульс по вертикальным и горизонтальным линиям данных;
  - ошибка — отметка у шага до завершения сценария.
- **Синхронизация:** с реальным выполнением и оверлеем; одновременно запущенные шаги подсвечиваются одновременно. Анимация не задерживает выполнение; завершение или отмена очищает индикацию.
- **Транскрибация:**
  - во время записи — индикатор на время запроса фрагмента и обработки ответа, импульс от записи при каждом запросе; индикация записи сохраняется;
  - после остановки — индикатор до завершения обработки остатка аудио и сборки текста; готовые фрагменты повторно не распознаются.

#### Готовые сценарии

- В общем списке отмечены тегом «Шаблон»; редактируются напрямую; название неизменяемо, кнопки удаления нет. Копии можно переименовывать и удалять.
- `reset_button` у них и их копий с подтверждением восстанавливает исходные шаги, триггеры и настройки; название и включённость сценария сохраняются. Без изменений кнопка неактивна.

**Язык и промпты готовых сценариев:**

- Транскрибация сохраняет исходные языки, письменность и переключения между языками; без перевода, ответа на вопросы и добавления отсутствующего в речи текста.
- Используй режим транскрибации и поддерживаемые параметры API: явно выбранный язык передавай, при «Авто» не подставляй фиксированный язык или язык интерфейса.
- `prompt` Groq Whisper — контекст, не системная инструкция. Не задавай универсальную подсказку на фиксированном языке; при неизвестном языке оставляй её пустой. Подсказки подбирай под исходную речь и ограничения провайдера; пользовательскую подсказку не заменяй скрытно.
- Постобработка исправляет текст по правилам сценария; ошибочный перевод при распознавании не исправляй догадками или обратным переводом.
- Проверяй решения на разных языках, смешанной речи и коротких фразах, с подсказкой и без неё. Используй только подтверждённые возможности; ограничения фиксируй, без обещания безошибочного распознавания.

### Логика сценариев

- **Запуск:** несколько сценариев могут быть включены с разными триггерами.
  - При конфликте триггер остаётся у занявшего его первым; предупреждение и блокировка этого триггера — только у последующих. Приоритет сохраняется после перезапуска.
  - Выполняется один сценарий за раз; его настройки фиксируются на время выполнения. Триггеры других сценариев в это время игнорируются.
- Сценарий задаёт шаги и передачу данных между ними. Каждый шаг явно описывает типы входных и выходных данных.
- **Параллельность:**
  - **Группа для `сквозное действие`** (`в буфер обмена`, `вставить в поле`): одновременно получают одни входные данные; после завершения всех действий исходные данные передаются следующему шагу.
  - **Ветки для `преобразование`** (`транскрибация`, `постобработка`, `озвучка`): одновременно получают входные данные шага-развилки; каждая независимо создаёт результат и выполняет собственное продолжение. Ветки могут разветвляться повторно; результаты автоматически не объединяются.
- Совместимые шаги соединяются по типам данных: выход предыдущего шага должен совпадать со входом следующего. Иначе приложение показывает причину.
- Основные типы данных:
  - `Аудио` — запись или её фрагмент;
  - `Текст` — обычный текст.
- Типы шагов:
  - `источник` — создаёт данные;
  - `преобразование` — меняет данные, даже если их тип остаётся прежним;
  - `сквозное действие` — использует данные и передаёт их дальше без изменений.
- **Ошибки:**
  - для `сквозное действие` — передача данных продолжается
  - для `источник` или `преобразование` — останавливается только своя ветка. Остальные ветки продолжаются; ошибки сохраняются у соответствующих шагов.
- Пользователь может добавлять и удалять шаги, менять их порядок и выбирать настройки и провайдеры. После изменения порядка приложение пересчитывает связи и показывает, если сценарий стал некорректным.
- Доступные шаги сценария:
  - `триггер записи` — `источник`; запускает запись и выдаёт `Аудио`;
  - `транскрибация` — `преобразование`: `Аудио` → `Текст`;
  - `постобработка` — `преобразование`: `Текст` → `Текст`;
  - `озвучка` — `преобразование`: `Текст` → `Аудио`; синтезирует и воспроизводит речь выбранным провайдером;
  - `в буфер обмена` — `сквозное действие`; копирует текст;
  - `вставить в поле` — `сквозное действие`; вставляет текст в активное поле.
- Сценарий завершается после завершения всех веток и параллельных групп и обработки очереди сохранения истории;
- Настройки сценария проверяются до начала записи. Если обязательный шаг не готов или нарушен порядок передачи данных между шагами, приложение показывает причину и не запускает сценарий.
- `ожидание записи`


#### Проверка повторов шагов

- **Случаи предупреждений:** в одном сценарии у включённых шагов совпадают тип и значимые настройки:
  - **Параллельные шаги** — получают данные из одного выхода.
  - **Последовательные `сквозное действие`** — между ними только `сквозное действие` или отключённые шаги.
  - **Шаги на разных уровнях разных веток** — получают данные из одного выхода напрямую либо через цепочки только из `сквозное действие` и отключённых шагов.
- **Значимые настройки:** влияют на результат или назначение действия; сравнивать итоговые значения с учётом наследования и значений по умолчанию. Оформление и уведомления не учитывать.
- **Поведение:** предупреждение у повторяющихся шагов; выбор, сохранение и выполнение разрешены. Шаги автоматически не удалять и не пропускать. Конфликты триггера записи проверяются отдельно.
- **Отображение:** жёлтый значок у «Настройки» раскрывает совпадения перед настройками, независимо от их раскрытия; «Показать шаг» — прокрутка и краткая подсветка. Хедер сценария всегда показывает число шагов с повторами; предупреждения обновляются при изменении шагов и настроек.

#### Процессы сценария:
- `запись`
  - `старт записи`: [](#триггер-на-кливишу) [](#звук-индикация-события)
  - `запись` [](#виз-индикация-процесса)
    Управление:
    - `отмена сценария`: [](#триггер-на-кливишу) [](#виз-индикация-процесса)
    - `пауза` / `возобновление`:
      - пауза: [](#триггер-на-кливишу) [](#виз-индикация-процесса)
      - возобновление: [](#триггер-на-кливишу) [](#виз-индикация-процесса)
  - `стоп записи`: [](#триггер-на-кливишу) [](#звук-индикация-события)
- `транскрибация` - трансрибация текста. [](#виз-индикация-процесса)
- `постобработка` - `преобразование` текста по промпту. [](#виз-индикация-процесса)
  Содержит:
  - обязательный поьзовательский промпт преобрзаования промпт как обязательный.
- `в буфер обмена` [](#виз-индикация-процесса)
  - **История:** текст шага всегда добавляется на «Уровень в истории» [](#настройка-из-панели-управления): целое ≤ 0; `0` — первый, `-1` — второй (по умолчанию). Уровень глубже истории — добавление в конец.
  - **Ctrl+V (Windows):** автоматически, без флага; независимо от уровня истории:
    - ручного копирования не было — текст шага;
    - было — последнее скопированное пользователем содержимое со всеми форматами.
  - **Учёт копирования:** от начала сценария до завершения этого шага. Служебные изменения буфера не учитываются; ручное копирование всегда приоритетно.
- `вставка в поле` - вставка текста в текущую позицию каретки (текстового курсора) активного текстового поля.
  Windows: вставляй текст через буфер обмена и Ctrl+V, затем восстанавливай прежнее содержимое буфера.
  Android: вставка через AccessibilityService в активное поле; без доступного поля — через подключение ввода (Android 13+). Если ввод недоступен, текст остаётся в буфере обмена.
  [](#звук-индикация-события)

Некоторые этапы в сценарии содержат готовность. Если не готов, то ошибка сразу при начале сценария:
- `триггер записи` (ПК) — обязательная клавиша запуска без конфликтов; ошибки видны у поля и в свёрнутых настройках шага.
- `трансрибация` - по готовности выбранного провайдера
- `постобработка` — по готовности выбранного провайдера и наличию непустого промпта пользователя

При `старт записи` проверяет системное разрешение. Если его нет:

- На Android запрашивай разрешения при действии требующего данное разрешения, при этом сохраняя состояние приложения. Для разрешения записи (микрофон): после предоставления разрешения автоматически продолжай начатый запуск записи; повторное нажатие кнопки записи не требуется.

- При отказе доступа показываем причину и действия: открыть настройки микрофона, повторить запрос или отменить запись.

- При отсутствии или занятости устройства показываем отдельную подсказку.
