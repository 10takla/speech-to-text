## UI

**Требования к UI:**
- адаптивные размеры - не задаем все явно, расчитваем на систему. элементы сами подстраиваются. Определяем порядок элементов, но не фиксированные размеры и позицию, только относительные.
- Компактное расположение элементов. Приложение вспомогательное, не должно мешать пользователю. Всё должно быть четко, лакончино и интуитивно понятно. Расчитываем на простое понимаение, а не подробное описание.

### На ПК:

Процессы:
- Трей: процесс приложения живет, сохраняясь в трее. При выходе из трея приложение завершает свою работу.

#### Окна:
- `панель управления`
  
  **Поведение в системе:**
  - окно отображается в панели задач
  - запускается из трея
  - запускается при открытии приложения
  
  **Компаненты панели:**
  - Различные настройки. Расположены в таком порядке:
    - импорт-экспорт-логи
      - `Экспорт` — копирует всю конфигурацию приложения в буфер обмена.
      - `Импорт` — открывает поле для ввода конфигурации в формате JSON.
      - `Скопировать логи` — копирует логи приложения в буфер обмена
    - `Запуск приложения` — Переключатель между (по умолчанию не выбрано):
      - открывать окно при запуске ОС
      - открывать свёрнутым в панели задач
      - запускать скрытым в трее (не в панели задач)
    - `Общие настройки:`
      - Настройки провайдеров.
      Если провайдеро на том или ином шаге больше двух, то находим у них общие настройки.
      В таком случае для каждого провадера в `Конретные настройки` будет выбор inherit от настройки из `Общие настройки`, либо задать конкртено.
    - [](#сценарии-в-панели-управления)
  - Настройки `desktop overlay записи`:
    - сброс позиции (по умолчанию по середине снизу)
  - Блок "История записей":
    - в хедере задается значение - число последних сохраненых записей
    - список записей сгруппированые по датам.
      Каждая запись отображает:
      - название сценария
      - время: час:минуты
      - шаги выбранного сценария:
        - каждый шаг остаётся на своём месте независимо от результата: выполнен, отключён, не выполнен или завершился ошибкой; шаги не группируются по статусу;
        - статус ошибки и её текст показываются непосредственно у шага с ошибкой; статус невыполненного шага — непосредственно у него;
        - результат каждого шага сразу сохраняется после его завершения;
        - шаги идут друг за другом без соединительных линий, уровней и отдельной группировки ошибок или невыполненных шагов

        **Оформление:**
        - шаги отображаются компактным списком строго в порядке сценария;
        - после шага `транскрибация текста`, прямо внутри него и перед следующим шагом, отображается результат как в режиме редактирования из [](#интерфейс-редактирования-записи), но только для просмотра:
          - сегменты сохраняют итоговое включённое или отключённое состояние, без возможности переключения;
          - воспроизведение доступно по полоскам;
          - курсором можно выделять и копировать любой текст, включая отключённые сегменты; кнопка «Копировать» копирует только включённые.

        
  - Всё остальное, что необходимо по всему описанию приложения.

  Горячие клавиши (глобальные, работают независимо от активного окна):
  - `старт/стоп записи` - по умолчанию `Ctrl+1` [](#ввод-клавиши) [](#настройка-из-панели-управления)
  - `пауза/возобновление` - по умолчанию `Ctrl+2` [](#ввод-клавиши) [](#настройка-из-панели-управления)
  - `отмена сценария` - по умолчанию `Escape`; останавливает выполнение сценария и сразу скрывает окно оверлея [](#ввод-клавиши) [](#настройка-из-панели-управления)

- `desktop overlay записи` - `окно оверлея`
  Свойства:
  - окно появляется:
    - виден от начала сценария до его завершения: после успешного выполнения последнего шага скрывается сразу, после ошибки — когда закончится показ ошибки
    - `Функция перемещения между мониторами`: регулируется по [](#значение-из-настройки). На мониторе, где находится мышка. При перемещении мышки на другой монитор - окно перемещается туда.
    - поверх всех окон
    - без иконки в панели задач
  - окно можно перетаскивать мышью. Позиция сохраняется при перемещении и не меняется при автоматическом изменении размера: [](#сохрание-в-настройках) [](#значение-из-настройки)
  - имеет максимальную ширину по отношению (0-100%, по умолчанию 50%) к размеру экрану монитора на котором находиться [](#значение-из-настройки)
    При появлении текста окно расширяется от центра в обе стороны. При достижении предельной ширины текст переносится на новую строку, а окно остаётся в пределах монитора.
    в настройках это:
    - [](#инпут-слайдер)
    - [](#динамичный-блок-скелет):
      - отобржается на мониторе в `окно оверлея`. 
        Изменение размера скелета происходит относительно блока оверлея.
        Позиция блока оверлея остается на месте, а блок скелета меняется по ширине, для этого меняется окно оверлея
      - высота транслирует высоту оверлея, меняется ширина

  **Состав блока оверлея:**
  - Отображение индикации шагов сценария, например:
    - записи:
      - статус: активна/неактивна
      - Во время `запись` отображается индикатор громкости входного звука (микрофона)
    - ошибки во время выполнения сценария
    - ошибку доступа или устройства с доступными действиями из раздела [](#доступ-к-микрофону)

  - Отображение `трансрибация в реальном времени`:
    - вкл/выкл `трансрибация в реальном времени` - флаг из [](#настройка-из-панели-управления) (по умолчанию вкл). В зависимости от флага отображаются настройки реально времени.

    Во время `запись` приложение отправляет аудио на распознавание небольшими фрагментами:
    - фрагмент завершается после паузы в речи: длительность задаётся [](#настройка-из-панели-управления) `Пауза для отправки` (по умолчанию 700 мс);
    - если речь продолжается, фрагмент отправляется по [](#настройка-из-панели-управления) `Максимум фрагмента`, по возможности у ближайшей паузы (по умолчанию 9 секунд);
    - соседние фрагменты перекрываются на [](#настройка-из-панели-управления) `Перекрытие фрагментов` (по умолчанию 0,5 секунды), чтобы не терять слова на стыках;
    - отображай весь накопленный текст записи с границами сегментов и отрывков, как в редакторе, но без полос проигрывания и действий редактирования;
    - после `возобновление` сохраняй весь текст и отметки удалённых сегментов из редактора; добавляй новую транскрибацию к этому тексту;
    - устраняй дубли распознавания перекрывающегося участка аудио; сохраняй реальные повторения слов в разных участках записи.

  #### Интерфейс редактирования записи:
  - `отрывок аудио`: При каждой `пауза` записи получаем отрывок аудио и отправляем на `трансрибация текста`. Транскрибаторы возвращают сегменты - привязка текста к времени в аудио. В оверлее появляется режим редактировани:
    - текст-транскрибация этого отрывка: визульно отображаются границы сегментов этого текста. При нажатии на сегмент или при долгом зажатии и проведении по сегментам, сегменты отмечаются как `удалённые` или наоборот `не удаленные`.
    - проигрывание аудио: под каждой строкой текста отображаются три уровня полос, сверху вниз:
      - первый — проигрывание отдельного сегмента;
      - второй — проигрывание отрывка;
      - третий — проигрывание всех отрывков записи вместе.
      Во время проигрывания соответствующие полосы и текущие сегменты подсвечиваются.
      
    Удаленные участки текста и аудио визуально синхронизируются между собой.

  - И так происходит при каждой `пауза`. В оверлее отображаются все `отрывок аудио` горизонтально с момента начала записи до момента `пауза` и доступны для такого редактирования. Отображение компактное по тексту. Сегменты текста отображаются как обычный текст, только выделена грница между ними. Аудио отрезок отображается по ширине текст.
  Во время `остановка записи` все отрывки не удаленные текста объединяются в один - это и есть выходной текст из транскрибации.

### На Android

- При нажатии на поле ввода в любом приложении показывай оверлей Android Bubble с кнопкой записи. Используй общий с ПК HTML/CSS/JS в WebView.
- По нажатию кнопки запускай запись и показывай управление: индикатор голоса, закрыть, пауза, стоп.
- Под кнопками показывай текст транскрибации; на паузе — в режиме редактирования.
- На паузе открывается редактор. «Продолжить» сохраняет изменения и возобновляет запись. После завершения записи текст вставляется в активное поле.
- Фоновая запись выполняется через службу с уведомлением.
- Уровни истории буфера Windows на Android недоступны.
- Проверять на реальном телефоне.

## Сценарии

### Сценарии в панели управления

Cтандартный сценарий доступен по умолчанию:
- `триггер записи`
- `транскрибация`
- `постобработка` (выключена по умолчанию)
- `в буфер обмена`
- `вставить в поле`

Интерфейс:
- **Хедер:** выбор (`selector`), создание (кнопка `add_button`), копирование (`copy_button`), переименование (`rename_button`) и удаление (с подтверждением) (`delete_button`) сценариев;
  **Требования:**
  - нельзя создать сценарии с одинаковыми названиями
  UI:
  - строка: `selector` + `rename_button` + `add_button` + `copy_button` + `delete_button`
  - по нажатию `rename_button`:
    - в `selector` появляется [](#инпут)
    - `rename_button` скрывается
  - по нажатию `add_button`:
    - в `selector` появляется [](#инпут) для ввода названия
  - после удаления:
    - `selector` переходит на `сценрий` расположенный после удаленного, иначе на до удаленного.
- **Шаги:**
  Шаги описаны в [](#сценарии-приложения).
  Настройки шагов находятся внутри раскрываемых шагов и сохраняются отдельно в каждом сценарии. Показывай только настройки, доступные на текущей платформе и в текущем состоянии шага. Если доступных настроек нет, не отображай блок «Настройки».
  Уточнения:
  - Для шага `запись` в раскрываемых настройках доступен выбор микрофона; по умолчанию — системный.
  - `Конкретные настройки` для провайдеров:
      При выборе провайдера отображаем его настройки.
      
      Для каждого провайдера изучаем его API на предмет того, что мы можем отобразить в настройках:
      - то, что может возвращать сам API для отображения в настройках, но при этом не расходует лимиты/квоты и прочие ограничения пользователя. Например: список моделей, параметры, языки и прочее. В связи с особенностью каждого провайдера.
      - то, что API не возвращает описываем вручную по документации

      **API-проверка конфигурации провайдера**
      Для каждого провайдера изучить, есть ли у него способ проверить параметры настроек без расходования лимитов/квот и прочих ограничений пользователя.
      Если есть, то создать **фукнцию-проверку**:
        - сделай автопроверку. Срабаотывает при:
          - при первой инициализации окна
          - при изменении только тех параметров, используемых в API-проверке. Локально проверяемые настройки не вызывают повторный запрос.
        - добавить для этого провайдера кнопку «Тест», которая будет делать это.
      **Функция-проверка** отражается на статусе шага.

      Важные настройки, без которых провайдеры не сработают, визуально выделяем.  
  
  Интерфейс. Редактирование состава и порядка шагов сценария.
    **UI редактирования:**
    - выбор стартового шага;
    - после выбора появляется элемент добавления следующего шага; список доступных шагов определяется типом выхода предыдущего шага;
    - настройки шага показываются при раскрытии его элемента и сохраняются отдельно для каждого сценария.
    - шаги с одинаковыми типами входа и выхода можно отключить; отключённый шаг остаётся в цепочке, помечается и передаёт данные дальше без изменения, его можно включить обратно.
    - после каждого шага сценария отображается бейдж/индикатор передаваемого типа данных (выход предыдущего → вход следующего).
    
    **Визуальное оформление шагов:**
    - шаги соединены общей линией; тип данных показывается на связи, без строки «Вход / Выход» внутри элемента.
    - `источник` обозначен точкой, `преобразование` — узлом `Δ` на линии;
    - у `сквозного действия` линия проходит через шаг и ответвляется к карточке.
    - после последнего шага можно выбрать совместимое продолжение; если его нет, отображается «Конец сценария».
    Например:
    - `[Шаг 1: Триггер записи] → [Аудио] → [Шаг 2: Транскрибация] → [Текст] → [Шаг 3: Вставить в поле] → [Текст] → [Шаг 4: В буфер обмена]`.

### Логика сценариев

- Сценарий задаёт последовательность шагов и передачу данных между ними. Каждый шаг явно описывает типы входных и выходных данных.
- Совместимые шаги соединяются по типам данных: выход предыдущего шага должен совпадать со входом следующего. Иначе приложение показывает причину.
- Основные типы данных:
  - `Аудио` — запись или её фрагмент;
  - `Текст` — обычный текст.
- Типы шагов:
  - `источник` — создаёт данные;
  - `преобразование` — меняет данные, даже если их тип остаётся прежним;
  - `сквозное действие` — использует данные и передаёт их дальше без изменений.
    - Ошибка сквозного действия не прерывает передачу данных; ошибка источника или преобразования останавливает сценарий. Ошибки сохраняются у соответствующих шагов.
- Пользователь может добавлять и удалять шаги, менять их порядок и выбирать настройки и провайдеры. После изменения порядка приложение пересчитывает связи и показывает, если сценарий стал некорректным.
- Доступные шаги сценария:
  - `триггер записи` — `источник`; запускает запись и выдаёт `Аудио`;
  - `транскрибация` — `преобразование`: `Аудио` → `Текст`;
  - `пост-процессинг` — `преобразование`: `Текст` → `Текст`;
  - `в буфер обмена` — `сквозное действие`; копирует текст;
  - `вставить в поле` — `сквозное действие`; вставляет текст в активное поле.
- Сценарий завершается после выполнения последнего выбранного шага;
- Настройки сценария проверяются до начала записи. Если обязательный шаг не готов или нарушен порядок передачи данных между шагами, приложение показывает причину и не запускает сценарий.
- `ожидание записи`


#### Процессы сценария:
- `запись`
  - `старт записи`: [](#триггер-на-кливишу) [](#звук-индикация-события)
  - `запись` [](#виз-индикация-процесса)
    Управление:
    - `отмена сценария`: [](#триггер-на-кливишу) [](#виз-индикация-процесса)
    - `пауза` / `возобновление`:
      - пауза: [](#триггер-на-кливишу) [](#виз-индикация-процесса)
      - возобновление: [](#триггер-на-кливишу) [](#виз-индикация-процесса)
  - `стоп записи`: [](#триггер-на-кливишу) [](#звук-индикация-события)
- `транскрибация` - трансрибация текста. [](#виз-индикация-процесса)
- `пост-процессинг` - преобразование текста по промпту. [](#виз-индикация-процесса)
  Содержит:
  - обязательный поьзовательский промпт преобрзаования промпт как обязательный.
- `в буфер обмена` - вставка в буфер обмена. [](#виз-индикация-процесса)
  Добавление в историю буфера обмена. Позиция новой записи задаётся числовой настройкой «Уровень в истории» [](#настройка-из-панели-управления) - целое число отсчет от 0 (первый) и в минус (`-1` — 2-ой [по умолчанию]) Если уровень глубже доступной истории, запись добавляется в конец истории.
- `вставка в поле` - вставка текста в текущую позицию каретки (текстового курсора) активного текстового поля.
  Windows: clipboard → Ctrl+V
  Android: вставка через AccessibilityService в активное поле.
  [](#звук-индикация-события)

Некоторые этапы в сценарии содержат готовность. Если не готов, то ошибка сразу при начале сценария:
- `трансрибация текста` - по готовности выбранного провайдера
- `пост-процессинг` — по готовности выбранного провайдера и наличию непустого промпта пользователя

#### Доступ к микрофону
При `старт записи` проверяет системное разрешение. Если его нет:
- Запрашиваем системное разрешение.
- На Android запрашивай разрешения при действии требующего данное разрешения, при этом сохраняя состояние приложения. Для разрешения записи (микрофон): после предоставления разрешения автоматически продолжай начатый запуск записи; повторное нажатие кнопки записи не требуется.
- Начинаем запись только после получения аудиопотока.
- При отказе доступа показываем причину и действия: открыть настройки микрофона, повторить запрос или отменить запись.
- Переход к настройкам Windows не включает разрешение автоматически: пользователь включает доступ самостоятельно.
- При отсутствии или занятости устройства показываем отдельную подсказку.
